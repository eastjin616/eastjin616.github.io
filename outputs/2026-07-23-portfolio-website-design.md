# 서동진 개발자 포트폴리오 웹사이트 디자인

작성일: 2026-07-23  
상태: 사용자 승인용 디자인 명세

## 1. 목적

서동진의 제조 현장 운영, 웹 개발, AI 서비스, 금융권 인프라 경험을 하나의 서사로 묶은 개인 개발자 포트폴리오 웹사이트를 만든다.

사이트의 목표는 기술 스택을 많이 나열하는 것이 아니다. 방문자가 짧은 시간 안에 다음 내용을 이해하도록 한다.

1. 백엔드 중심 풀스택 개발자다.
2. 화면, 서버, 데이터, 운영을 함께 본다.
3. 제조 현장과 대규모 운영 경험이 개발 방식에 영향을 주었다.
4. 대표 프로젝트에서 문제를 어떻게 분해하고 해결했는지 증명할 수 있다.

주요 방문자는 개발자 채용 담당자, 실무 개발 리더, 면접관이다.

## 2. 핵심 포지셔닝

### 한 문장

> 현장에서 쌓은 운영 감각 위에 소프트웨어를 쌓아온 백엔드 중심 풀스택 개발자

### 확장 문장

> 화면, 서버, 데이터와 운영을 연결해 실제 환경에서 오래 쓰이는 서비스를 만듭니다.

### 커리어 서사

```text
설비·공정 운영
→ 웹 백엔드와 데이터 흐름
→ AI 제품과 개발 자동화
→ 금융권 서비스 연속성과 장애 대응
```

각 단계는 이전 경험을 버리고 새로 시작한 경력이 아니라, 새로운 레이어가 추가된 과정으로 표현한다.

## 3. 디자인 콘셉트

### 메인 콘셉트: Diffusion Layers

SK하이닉스 Diffusion 공정 경험과 개발 역량이 층층이 쌓인 커리어를 연결한다.

- 웨이퍼와 박막 레이어를 연상시키는 원형 그래픽
- 미세한 격자, 동심원, 반투명 표면
- 경력을 `Physical`, `Backend`, `AI Product`, `Reliability` 레이어로 표현
- 기술을 나열하기보다 어떤 관점이 추가됐는지를 보여줌

### 프로젝트 표현 방식: Routing Map

프로젝트 상세에서는 요청과 데이터가 이동하는 경로를 노드로 보여준다.

```text
문제
→ 제약
→ 판단
→ 시스템 구성
→ 실패·복구
→ 결과
```

이 구조는 백엔드 개발자의 사고방식과 운영 관점을 시각적으로 증명한다.

### liquid-dom의 역할

liquid-dom은 사이트의 정체성이 아니라 다음 부분을 표현하는 보조 도구다.

- 히어로 웨이퍼 위에서 움직이는 굴절 렌즈
- 레이어 경계가 합쳐지거나 분리되는 전환
- Routing Map의 핵심 판단·복구 노드
- 프로젝트 전환 시 짧은 표면 왜곡

텍스트, 링크, 내비게이션과 프로젝트 본문은 일반 HTML로 유지한다.

## 4. 시각 시스템

### 색상

- 기본 배경: 차가운 실버 그레이
- 본문: 잉크에 가까운 네이비
- 프로젝트 영역: 따뜻한 블랙과 회녹색
- 레이어 포인트: 스틸 블루, 옅은 바이올렛, 세이지, 살구색
- 상태 및 라우팅 강조: 절제된 라임 그린

네온 그라데이션, 과도한 글로우, AI 제품 랜딩페이지에서 흔히 보이는 보라색 블롭은 사용하지 않는다.

### 타이포그래피

- 영문 대형 제목: 에디토리얼 성격의 세리프
- 한글 및 본문: 높은 가독성의 산세리프
- 레이어 번호, 날짜, 시스템 상태: 모노스페이스

큰 영문 제목은 분위기를 만들고, 실제 설명과 프로젝트 내용은 한글로 명확하게 전달한다.

### 그래픽 원칙

- 장식용 아이콘을 반복하지 않는다.
- 프로젝트마다 로고보다 문제와 구조를 보여준다.
- 실제 화면, 시스템 다이어그램, 전후 비교를 우선한다.
- 모든 움직임은 커리어 레이어 또는 데이터 흐름을 설명해야 한다.

## 9. 브라우저 지원과 폴백

liquid-dom 렌더링에는 WebGPU가 필요하다. DOM-backed `Html` 기능은 사용하지 않는다.

### WebGPU 지원 환경

- 웨이퍼 렌즈 굴절
- 레이어 전환
- Routing Map의 액체 노드

### WebGPU 미지원 환경

- 정적 웨이퍼 SVG 또는 CSS 그래픽
- 반투명 CSS 원형 렌즈
- 모든 텍스트와 링크 정상 노출

### 모션 감소

`prefers-reduced-motion: reduce`에서는 다음을 적용한다.

- 자동 회전과 포인터 추적 중지
- 짧은 페이드만 사용
- Routing Map 노드를 고정

## 10. 접근성

- 콘텐츠를 캔버스에만 넣지 않는다.
- 시맨틱 제목 순서를 유지한다.
- 모든 프로젝트와 링크는 키보드로 접근 가능해야 한다.
- Routing Map 외에도 일반 목차를 제공한다.
- 색상만으로 레이어와 상태를 구분하지 않는다.
- 장식용 캔버스는 보조기기에서 숨긴다.
- 본문 대비는 WCAG AA를 목표로 한다.

## 11. 성능 원칙

- 초기 HTML과 핵심 CSS가 먼저 표시된다.
- liquid-dom과 WebGPU 코드는 첫 화면 이후 지연 로드한다.
- 큰 이미지에는 반응형 크기와 압축 포맷을 사용한다.
- 스크롤마다 React 상태를 갱신하지 않는다.
- 애니메이션은 transform과 opacity를 우선한다.
- 대표 프로젝트 세 개만 홈에 렌더링한다.

## 12. 오류 처리

- WebGPU 초기화 실패 시 정적 폴백으로 전환한다.
- 캔버스 오류가 일반 콘텐츠 렌더링을 막지 않게 격리한다.
- 이미지가 없거나 실패해도 프로젝트 제목과 설명은 유지한다.
- 외부 데모가 중단돼도 프로젝트 설명과 GitHub 링크는 남긴다.
- 비공개 프로젝트에는 작동하지 않는 링크 대신 공개 범위를 명시한다.

## 13. 검증 계획

구현 후 다음을 확인한다.

1. WebGPU 지원·미지원 환경에서 핵심 콘텐츠가 동일하게 보이는가
2. 데스크톱과 모바일에서 읽는 순서가 자연스러운가
3. 키보드만으로 모든 링크와 프로젝트를 열 수 있는가
4. 모션 감소 설정에서 애니메이션이 중지되는가
5. 프로젝트 URL을 직접 공유할 수 있는가
6. 공개 금지 정보가 포함되지 않았는가
7. 이력서·경력기술서·포트폴리오의 날짜와 기술이 일치하는가
8. 빌드, 타입 검사와 정적 검사가 통과하는가
